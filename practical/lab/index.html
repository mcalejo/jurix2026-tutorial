Two words you need. A twin is a program of another system, translated into Logical English (LE). A scenario is a set of facts. A scenario also gives the answers that it expects, so it is a test. The expected answers of each twin come from the engine of the other system.

1 · A LegalRuleML twin 6 minutes

LegalRuleML is the OASIS standard for legal rules in XML. This document comes from the LegalRuleML specification: section 29 of the Australian National Consumer Credit Protection Act 2009. A person must not engage in a credit activity without a credit licence.

Open the twin in the LE editor

  1. Select File ▸ Show the Original…. The LegalRuleML file opens. Find lrml:Prohibition. Then find rule ps1 in the twin.
  2. Make sure that the scenario is unlicensed_trader and the query is obligations. Click Query.
  3. Click the first answer. Read the explanation: which rule and which facts make the answer true?
  4. Select the scenario licensed_trader and the query prohibitions. Click Query. There is no answer.
  5. Click Why not. Find the condition that is not true for Bob.
Answers
  • Step 2 gives two answers: Alice must pay 200 penalty units, and Alice must pay 2000 civil penalty units.
  • Step 3: rule reparation_1_1 gives the 200 penalty units. Its condition is that Alice violates the prohibition of rule ps1: Alice is a person, Alice has no credit licence, and Alice engages in a credit activity.
  • Step 5: the condition that fails is it is not the case that bob holds a credit licence. Bob holds a licence. That is section 29(2): the prohibition does not apply to a licensee.

2 · A Drools twin 6 minutes

Drools is a rule engine for Java. Its rules change a working memory, a store of facts. In the twin, the facts are states of the world, and each change is an event. This twin is written for LPS (Logic Production Systems), the extension of Logical English for events and actions in time.

Open the fire alarm in the LPS editor

  1. Read the rule under the comment Rule "RaiseAlarm". Then select View ▸ The original this was converted from and find the same rule in the Drools file.
  2. Click Run.
  3. On the Timeline, find the cycle where the fires start, and the cycle where the alarm goes on.
  4. Right-click the event an alarm goes on. Which rule made it happen?
  5. Read the comment above the scenario driver. It gives the facts that Drools had at the end. Compare them with the last state of the twin.
Answers
  • Step 3: the fires start at cycle 11. At cycle 12 the sprinklers turn on and the alarm goes on. The fires are put out at cycle 21, and at cycle 22 the sprinklers turn off and the alarm goes off.
  • Step 4: the twin of the Drools rule RaiseAlarm: there is a fire in a room, and no alarm is on.
  • Step 5: at the end, Drools has the four rooms and the four sprinklers, and no fire and no alarm. The twin ends in the same state.
  • The rules that only print text in Java are not translated. They stay in the twin as TODO comments, with their Java.

3 · Break a rule 8 minutes

Go back to the LegalRuleML twin of exercise 1. You change a rule, and the scenarios tell you what you changed.

  1. Find rule ps1. Delete its last condition: 
    rule ps1:
a party is forbidden that the party engages in a credit activity if
    the party is a person
    and it is not the case that the party holds a credit licence.
    The rule must now end with the party is a person. (with a full stop).
  2. Select Misc ▸ Run the Program's Tests….
  3. Which scenarios fail? For each failure, read the expected answer and the actual answer.
  4. Ask the question permissions in the scenario licensed_trader. Then ask prohibitions. What is strange?
  5. Put the condition back. Run the tests again: all of them must pass.
Answers
  • Step 3: five tests fail, all in the scenario licensed_trader. Bob is now forbidden to engage in a credit activity, so he violates the prohibition, he must pay the penalties, and he is in breach. The other three scenarios still pass: nobody in them holds a licence, so the deleted condition was true for each of them.
  • Step 4: Bob is permitted (rule ps2) and forbidden (the changed rule ps1) to engage in a credit activity. Two rules are in conflict. LegalRuleML can say which rule wins (defeasible rules, with an order between them). The original text avoids the conflict with the exception in section 29(2).
  • The lesson: a scenario with its expected answers is a test. A small change to a rule shows at once where its answers change.

More, if you finish early

  • Open a file of another system yourself. Download the LegalRuleML file or the Drools discount rules. In the LE editor, select File ▸ Open… and open the file. The translator writes the twin. This needs the workshop account: ask us for it.
  • Other twins. In the LE editor, select File ▸ Open example from server… and look in the folder migration: Blawx, Catala, DMN, Epilog, L4, Bitcoin Miniscript, Axiom RuleSpec, s(CASP). Each folder has a README with steps to try.
  • Logical English in French. Open fr/citoyennete. Add a scenario, in French, for a child who is born in France. Run the query. Also in Portuguese (pt/cidadania), Spanish (es/ciudadania) and Italian (it/cittadinanza).
  • Write a rule from text, with a language model. In the LE editor, open the LE Assistant tab at the bottom. Paste a short article of a regulation, and ask for the rules and one scenario. Then write a second scenario yourself, and run the tests. The model writes the draft; your scenarios decide.

Words used on this page

  • Template: the pattern of a sentence, with slots for values, for example *a person* holds a credit licence.
  • Query: a question to the program.
  • Explanation: the rules and facts that make an answer true. Click an answer to see it.
  • Why not: the conditions that fail, when a query has no answer.
  • Fluent (in LPS): a fact that can change in time, for example an alarm is on.
  • Cycle (in LPS): one step of time on the timeline.
